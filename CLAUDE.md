# TurboDocs: project handoff

Read this first, then `PROJECT_BRIEF.md`. This file is the running state and decision log: update it whenever a decision or the state changes.

## Engine
This app is pinned to TurboNZL/turboengine (see `.turboengine.json`; `docs/development/ENGINE.md` says which modules and where they live). The engine is a **reference, not a dependency**: its modules are working code copied into apps (only `turbothemes` is installed as a package). Before building something that every app would want (updates, release naming, the theme picker, window chrome, settings layout, guides), look in the engine's `modules/` first and copy from it rather than inventing a new one. If you improve a module here, say so in the session log so it can be ported back to the engine.

## User preferences (how to work with them)
- Don't waste their usage. Fact-check and double-check yourself; use web search liberally.
- They write casually; reply in normal capitalised prose, not lowercase or slang.
- Put effort into verifying against real runs, not only unit tests.
- A merged PR cannot take new work: restart the branch from main for follow-up changes. Commit trailers as the harness gives them. Do not create a pull request unless asked.

## Hard-won gotchas
- `pnpm install --ignore-scripts` (CI) skips the Electron binary: run a plain `pnpm install` locally.
- turbothemes is pinned by commit: `git+https://github.com/TurboNZL/turboengine.git#<commit>&path:/themes` (same commit as `.turboengine.json` `engine.ref`). With a commit in the specifier pnpm records an https tarball (codeload) in the lockfile, which CI can fetch; WITHOUT a commit it writes an SSH address (`git@github.com:...`) that CI cannot clone and that had to be fixed by hand. Never drop the commit. `docs/development/ENGINE.md` says how to update the pin.
- Icons are generated from `branding/logo.json` (engine `logos` module): never edit them by hand.
- `pnpm/action-setup@v4` fails if the version is given both in the workflow (`with: version`) and in `package.json` `packageManager`. TurboDocs keeps it only in `packageManager`. The engine's `release-pipeline` workflows pin `version: 10`, so any app that sets `packageManager` hits this; port the note back.
- The window loads the client from `http://127.0.0.1:47815` (fixed port) so its storage keeps the user's look. Change it only with `TURBODOCS_DESKTOP_PORT`.
- `auto-pr.yml` ignores `legacy/**` so the legacy branch never gets a PR against main.

- A second launch must not start up: `app.quit()` is asynchronous, so without the `primary` guard in `main.ts` the second process found the port taken and opened an unclosable error dialog. The engine's `window-frame/main.ts` has the same pattern and should get the same guard.
- The "Automatic" graphics mode relaunches the app up to five times when there is no GPU (a headless sandbox): set `TURBODOCS_SOFTWARE_RENDERING=1` when driving the app from a script.

- Word draws bullets with private-use Symbol/Wingdings characters (U+F0B7 ...) that Linux lacks: `fixSymbolBullets` in `pages/View.tsx` maps the common ones to Unicode. Other Symbol glyphs fall back to a plain bullet.
- `apps/web/src/fonts.css` is generated (`node apps/web/scripts/gen-fonts.mjs`, then `pnpm add` the packages it prints). Re-run it after updating turbothemes.
- The page may read only files that came through Open, the command line or the system (`allowed` in `main.ts`). New features that read files must go through the same list.

- The importer uses `@xmldom/xmldom`, not the browser's DOMParser, so the same parser runs in the app and in the tests (happy-dom's DOMParser is not a real XML parser).
- React 19 sets attributes of a custom element as properties when the element has a member of that name: `<turbo-themes-picker sections="...">` replaces the element's private `sections()` method and throws. `AppearancePicker.tsx` creates the element with `setAttribute` (`StockPicker`).
- A click in the empty area below the text lands on the editor's root element and leaves the caret at offset 0 (typing then goes to the START). `DocPane` moves the caret to the end in that case.
- While a document has unsaved changes, opening another file (second launch, Open) raises a blocking `window.confirm`: a script driving the app (CDP) hangs on it. Save or restart the app between runs.
- Slides: `SlideCanvas` draws the whole slide twice on purpose (the `SlideStage` underneath, the interactive layer on top), so anything a static draw adds (a bullet on an empty paragraph, a hint) shows through: static drawing skips bullets on empty paragraphs and shows hints only in the canvas layer.
- Slides: resizing a turned box must keep the opposite edge fixed on the slide, so the new frame is computed in the box's own axes and then moved by the difference of the anchor's world position (`SlideCanvas.tsx`). Aligning, snapping and the marquee use `bounds()` (the turned box's outer rectangle), not the raw frame.
- Slides: after Tab in a table cell the next cell's editor must mount in the same React batch (no `setTimeout`), or the first typed letters are lost.
- Slides: `Para.num` uses CSS counters (`.slide-p[data-num]`), reset on every paragraph that is not numbered; the paragraph's font size comes from its first run so the number is as big as the text.
- Sheets: frozen panes are three extra layers (top, left, corner) over the scroller, each drawn with the same `renderCell`, selection and editor; `cellAt` does not add the scroll offset inside the frozen area. Pinned headers are a second set of headers on top of the scrolling ones.
- Sheets: charts are positioned in sheet px (not cells) and written to xlsx as `oneCellAnchor` with an EMU size; the cell is found with our own default row/column sizes, so a chart sits a few px off when another program uses its own default sizes. `xlsxCharts.ts` reads only column-oriented series in neighbouring columns of the same sheet; anything else is listed in the warnings.
- pptxgenjs cannot write slide transitions or picture crops: `patchSlides` in `pptx.ts` edits the finished slide XML (`<p:transition>` after `</p:clrMapOvr>`, `<a:srcRect>` before `<a:stretch>` of the n-th `<p:pic>`). It also omits covered table cells (the library wants rows without them) and writes a missing chart number as 0.
- Slides charts reuse `sheets/ChartView.tsx` with an `ink` (the slide's text colour) instead of the page's theme tokens. A chart's categories in a pptxgenjs file are in `multiLvlStrCache`, in other tools `strCache`: the reader accepts both.
- Sheets rules (`rules.ts`) are pure: `cfEvaluator` (first matching rule wins), `validate`, `hiddenRows`. Filtered rows get height 0 in the grid and `hidden="1"` in the file, and a filter's allowed values are compared with the cell's shown text.
- In headless Chromium a real-fullscreen show cannot be closed by Esc through Playwright (the browser eats it and fires `fullscreenchange` late); press Esc then an arrow key. On a real desktop Esc works.
- Pointer capture redirects the click and double-click to the capturing element: the grid captures the pointer on press, so `dblclick` is handled on the grid and the cell is found by position (a handler on each cell never fired in a real browser).
- Sheet sizes: a column `width` in a file is characters x 7 px (padding included; the old `x 7 + 5` made every column 5 px too wide), the sheet's `sheetFormatPr` gives its default column width / row height (Google: 12.63 / 15.75 pt), a row's `ht` is kept even without `customHeight` (rows grown to fit wrapped text). `Sheet.defColW` / `defRowH` carry them; use `colWidth` / `rowHeight`, never the bare constants.
- `OverflowBar` measures with everything drawn (layout effect, before paint) and hides trailing groups behind the More button; the toolbar must not clip (`overflow: hidden` clipped the More panel), and a Popover's own menus are portaled, so its outside-click check ignores `.bt-menu`.
- A listener that is removed and added again on every render (`useEffect` without a stable handler) can be swapped in the MIDDLE of a key press: another listener's state change re-renders in a microtask, and a listener added during dispatch is not called for that event. That is why Esc did not close dialogs. `Dialog` and `ContextMenu` now keep one listener and call the latest callback through a ref; the Slides page handler ignores keys while a `[role=dialog][aria-modal]` is open.
- Sheets: copy, cut and paste are listened for on the `document` (`Grid.tsx`), not on the grid element: the browser aims them at its text caret, which can be inside a sheet tab after a click, and then the grid never saw them.
- Sheets: long text runs on over empty cells to its right (Google's "Overflow" wrapping) by widening the cell and not drawing the cells it covers; a click there is mapped by pointer position (`cellAt`), not by the cell that owns the text.
- Sheets: Playwright's `locator('button:has-text("Insert")')` also matches the menu bar's Insert: scope to `[role=dialog]`.
- When driving the editor with a script, wait ~250 ms after closing the link popover before the next keystroke: TipTap hands focus back asynchronously, and `Enter` with the line still selected replaces it.
- The Python version's .deb and the new one are both the package `turbodocs`; the old one put its logo at `/usr/share/icons/hicolor/scalable/apps/turbodocs.svg`, and `~/.local/share/{applications,icons}` + `~/.local/bin/turbodocs` from its `install.sh`. A stale scalable icon beats a PNG in most icon themes, so the new .deb ships the SVG at the same path (`apps/electron/scripts/prepare-icons.mjs` copies the generated logo before packaging; fpm maps it). The old per-user files must be removed by the user (`scripts/uninstall-legacy-python.sh`).
- The packaged window icon is `process.resourcesPath/icon.png` (an `extraResources` entry): a path inside `app.asar` is not readable for `BrowserWindow.icon`.
- Imported documents keep their own text styles and page setup (`DocStyles` in `docxImport.ts`, `styleVars` in `docStyles.ts`); new documents use `FACTORY_STYLES` (A4). The Google Docs export has `xmlns=` default-namespace noise on the root: harmless, the reader works on `w:` names.
- A script driving the app: wait for the debug port before opening a file, otherwise the file launch wins the single-instance lock and the debug instance quits.
- StarterKit's trailing node keeps an empty paragraph at the end after a list or table; it is exported as an empty paragraph.
- DOM `img` counts in the editor include ProseMirror's spacer images; count pictures in the saved file instead.
- The page may only WRITE to files it was allowed to read (or chose in Save as), and only types a module opens; writes are atomic (temp file + rename) after a backup.

- A button that keeps the keyboard focus eats typing: after "Add tab" the Space bar clicked it again (4 spaces = 4 new tabs). Anything that opens a panel and then expects typing must move focus to the editor (`editor.chain().focus()`), see `OutlinePanel.jumpToTab`.
- `docx` writes an empty `<a:srcRect/>` after every picture's blip: a crop must REPLACE it (two `srcRect` in one picture is invalid), see `patchCrops`.
- Chromium's `zoom` and sticky headers do not mix with `transform: scale`: the sheet grid keeps its headers outside the scroller and moves them by the scroll offset (`Grid.tsx`).
- Slide text is `contentEditable`; the toolbar uses `document.execCommand` with `styleWithCSS` and the box is read back from computed styles (`rich.tsx readParas`). Font size has no execCommand: it asks for size 7, then rewrites the `xxx-large` spans (the classic trick).
- tint and shade in a PowerPoint colour are done in linear light, not in HSL (a grey subtitle came out dark otherwise).
- In Playwright, `page.click('.docs-editor')` clicks the box's centre, which may be a table or picture: click a text line instead, or typing goes nowhere. And `text=Restore` matches the banner's sentence before its button: use `button:has-text("Restore")`.
- Electron: `queryLocalFonts()` needs no permission and no gesture (`system-fonts`), because the window's origin is `http://127.0.0.1:47815`, a secure context.
- A `pkill -f "electron.*turbodocs"` inside a script whose own command line contains those words kills the script's shell: use `pkill -x electron`.
